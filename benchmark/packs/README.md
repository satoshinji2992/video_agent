# VideoAgentBench 输入素材包 v1

构建日期：2026-11-01　　状态：**v1 已冻结**

这里是 VideoAgentBench（`../benchmark-v0.2.md`）三个任务的固定输入。所有参测系统、所有轮次都用同一份文件，保证输入一致。

## 冻结规则

- v1 已冻结。任何文件都不要原地重新生成、覆盖或修改。
- 需要改素材时，新建一个版本目录（例如 `v2/task2-coffee/`），在新目录里生成，并在本文件末尾的“版本记录”里写清改了什么。v1 保持原样。
- `SHA256SUMS` 记录了 v1 每个文件的校验值。`../scripts/fetch-packs.sh` 下载解压后会自动校验；手动校验时在本目录执行 `sha256sum -c SHA256SUMS`，全部 OK 再开始。
- 素材包（视频、图片、音频）不在 git 里，作为 GitHub Release 的附件分发，每个任务一个 zip，zip 的校验值在 `ZIPSUMS`。

## 运行方式（给运行方）

1. 每次运行前执行 `sha256sum -c SHA256SUMS`。
2. Stage A：只给参测 Agent 两样东西：`user_prompt.txt` 的原文（作为用户消息原样发送，不改写、不补充说明），以及该任务 `assets/` 目录的一份新副本。Task 1 的 `assets/` 只有一行说明。
3. 不要给 Agent：`revision_prompt.txt`、`task_metadata.json`、`evaluator/`、本 README、`benchmark/tools/`。
4. Stage B：Agent 交付第一版成片（`final_v1.mp4`）之后，才打开 `revision_prompt.txt`，把原文作为用户的下一条消息发给同一个 Agent 会话。
5. `evaluator/` 只给评测方。`manifest.json` 记录每个文件的提示词、模型、分辨率、时长、用途、有意瑕疵（none / shaky / duplicate / overexposed / invalid）、重试次数和 sha256；`overview.png` 每段素材一帧并带标签。
6. Task 1 的事实以 `task_metadata.json` 里的 `fact_check_date`（2026-11-01）为准。

## 生成方式

- 日期：2026-11-01。
- 视频：Seedance 2.5（`doubao-seedance-2-5-260628`），经中转站调用，分辨率 1080p（Task 2 竖屏 1080×1920，Task 3 横屏 1920×1080），24 fps，视频编码为 Seedance 原样输出的 HEVC（H.265）Main 10（10-bit 4:2:0），样片（draft）模式关闭，同步生成现场声（AAC 32 kHz 立体声）。开工前先用一段 5 秒 1080p 测试片确认服务端接受 1080p；这段测试片质量合格，就是现在的 clip06_grinding。
- 图片：gpt-image-2 用于需要准确中文的画面（菜单、Logo、门头招牌、黑板首帧）和店主照片；Seedream 5.0（`doubao-seedream-5-0-260128`）用于写实场景（店内、咖啡豆、拿铁、窗边座位、公寓和走廊底图）。
- 一致性：
  - 需要文字或固定场景的镜头，先生成静帧再作为 Seedance 首帧：门头（招牌文字）、黑板（菜单文字）、店内、窗边座位，以及 Task 3 的客厅、走廊、厨房台面、玄关柜、挂钟底图。
  - Task 3 里成对的镜头用同一张首帧，空镜和有人的镜头机位一致。
  - 服务端拒绝含写实人脸的图片（无论作为参考图还是首帧），也不允许首帧和参考图混用。所以店主和 Task 3 女主都靠固定的文字描述和固定服装保持一致，并尽量用背影、侧面、远景或只拍手的构图。有人物、没有首帧的镜头用无人的场景图作参考图。
- 审片：每一次生成都做了 6 帧联系表并人工看过；用首帧生成的片段另外看了开头 1.4 秒（发现并处理了 clip12 开头的瑕疵）；黑板和招牌文字用全分辨率截图核对；有台词的片段用 Whisper 核对台词，所有片段用 Whisper 排查意外人声；晃动用帧间位移量化；Task 3 的固定机位用相位相关法测了与底图的位移；挂钟秒针测了角速度。没有人工逐条“听”过音频，音频只用频谱图、响度和转写检查。
- 重试：每段最多重试 2 次（含首次共 3 次）。共生成 40 次（含被弃用的），另有 3 次测试请求在提交时被拒（未生成、未计费）。重试的片段和原因：clip08（背景不像本店）、clip09（拉花的人脸部入镜且不像店主、图案不对）、clip17（第 1 条出现菜单上没有的可颂，第 2 条顾客背着类似奢侈品牌图案的包）、Task 3 clip07（第 1 条景别和挂钟位置不对，第 2 条视线方向与挂钟位置矛盾）。
- 后期处理（其余视频文件与 Seedance 原始输出逐字节相同，`manifest.json` 的 `source_sha256` 可核对）：
  - clip12_window_seat：原片 0.4–0.6 秒有生成瑕疵，裁掉开头 0.8 秒，视频用 x265 重新编码成同样的 HEVC Main 10（CRF 16），音频原样复制。
  - clip13_window_seat_2：首帧是窗边座位静帧经过调色模拟的过曝版本，过曝本身由 Seedance 在整段里延续。
  - ambience：截取、淡入淡出、重采样到 48 kHz、按响度统一增益。
- Seedance 总生成时长与费用：见下方“费用”。

## 费用

- Seedance 共生成 40 次，请求时长合计 355 秒（实际输出 357.6 秒）：
  - Task 2：178 秒（含 5 秒 1080p 测试片），18 段成片共 143.4 秒；
  - Task 3：177 秒，12 段成片共 99.7 秒，另有 4 段各 16 秒的空场景用来提取环境声。
- 另有 3 次测试请求在提交时被拒，没有生成，也没有计费。
- 中转站按人民币计费，1080p 每次的费用 = 0.15592 元 ×（24 × 秒数 + 1），即约 3.76 元/秒（10 秒一段 37.58 元）。
- 28 次有实际扣费记录，合计 947.40 元。另外 12 次的账单查询一直返回 HTTP 429，费用按上面的公式推算，合计 387.32 元；公式与全部 28 条实际账单完全吻合。
- 视频合计 1,334.69 元，按 1 美元 = 7.2 元约合 185.4 美元。其中 Task 2 为 669.54 元，Task 3 为 665.15 元（含环境声来源）。每次请求的任务号和费用依据记在各 `manifest.json` 的 `attempts` 里（生成时的完整日志没有公开）。
- 图片：gpt-image-2 共 22 张、Seedream 共 24 张（23 次调用），中转站没有单张计费查询，按估价约 1.6 美元。

## 已知限制

- 人物脸部：因为不能用写实人脸做参考，同一个人在不同片段里的脸会有差异（发型、服装一致）。Task 2 的女店主在 clip16、clip18 里正脸出镜，看起来比资料里写的 32 岁年轻；店主合影照片（photos/owners.jpg）和视频里的店主长相不完全相同。
- 围裙：两位店主都系带皮质肩带的帆布围裙，但颜色在灰褐、深棕、深灰之间有出入。
- Task 3 clip08 的秒针是连续扫动，比真实挂钟快约 14%。
- Task 3 clip07 是过肩镜头，抬头动作比较轻。
- 店里的吧台、窗户在不同片段里细节不完全相同（同为深绿色窗框、浅色木吧台、白墙、旧木地板）。
- 所有素材都是 AI 生成的仿手机原始素材，评测时不应以“不是实拍”为由扣分。

## 生成工具（../tools/）

不属于素材包，不给参测 Agent，评测也用不到；公开出来是为了能复现或扩充素材：

- `specs/`：所有片段和静帧的提示词与参数，路径相对 `benchmark/tools/`。
- `scripts/`：生成、检查和整理脚本，调用本仓库 `src/` 里的 Seedance 与图片接口。用 `scripts/run.sh <脚本>` 运行（读仓库根目录的 `.env`）；Python 脚本直接用 `python3 -I`。
- 运行时会在 `benchmark/tools/` 下生成 `work/`（候选片段、静帧、联系表）、`log/`（每次请求的记录）、`tmp/`、`data/`，这些目录不进 git。生成 v1 时的原始片段和日志没有公开。
- 素材按 v1 冻结规则只能生成到新版本目录，不要覆盖 v1。
