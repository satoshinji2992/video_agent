# How agents produce short ad videos: the production pipeline and when to use code animation or generative video

Research date: 2026-10-31. Most sources date from 2025–2026. "Code path" means motion graphics written as code and rendered deterministically (HyperFrames, Remotion, Claude Motion). "Gen path" means generative image-to-video or text-to-video models (Veo, Kling, Seedance, Grok Imagine and others). Vendor-authored or secondary sources are flagged inline. Everything under "Inferences" is my synthesis for the Claude Agent SDK demo (Linux, Node, Python, FFmpeg, headless Chrome), not a sourced fact.

---

## Q1. What are the standard stages (brief → … → variants), and which tools are used at each?

### Takeaway
Production ad agents and open-source pipelines follow nearly the same stages:
1. Brief, plus ingestion of the product URL and brand.
2. Selling points.
3. Hook, script and beat sheet.
4. Shot list with durations.
5. Reference stills or keyframes, approved before any motion is made.
6. Motion for each shot, either rendered from code or generated by image-to-video.
7. TTS with timing data.
8. Music, with a beat grid and ducking.
9. Captions timed word by word.
10. Deterministic assembly in a headless-Chrome renderer, or in FFmpeg/MoviePy.
11. Layered automated QA: linting and layout checks, sampled frames and contact sheets judged by a vision model, and FFmpeg signal checks.
12. Variants, made by re-rendering with different parameters.

As of late 2026 the most agent-ready toolchain is the HyperFrames CLI. Every step (lint, check, snapshot, transcribe, tts, beats, render --batch, diff) is a command, and most take `--json`. Remotion with its official agent skills is the React alternative.

### Cited Findings

#### End-to-end stage maps from real systems
- **Creatify Agent** is a commercial closed-loop multi-agent ad system with a public tech report. It runs these stages:
  - A **Producer** ingests the brief and outputs a scene plan plus a typed **asset graph**. The graph covers product facts, persona descriptors, brand state and required on-screen text.
  - **Web research and URL ingestion** extracts brand identity (name, concept, palette, hero imagery). It can also search TikTok and Instagram for category references.
  - **Reference-video decomposition** extracts shot rhythm, color, camera language, transitions and the cadence of on-screen text.
  - **Directors** choose "models and parameters per shot".
  - **Audio scoring** writes music timed to the cut cadence. A separate TTS layer handles voiceover, and both are composited at known offsets.
  - A **typography layer** composites text, such as the brand mark on the end card.
  - A vision-model **Critic** "evaluates each rendered scene against the asset graph along an explicit rubric". A failing scene is regenerated on its own; the whole ad is not re-rolled.
  - **Persistent brand memory** carries facts and preferences across sessions.
  - Skills (UGC, product demo, testimonial, motion-design, comparison) are chosen based on the brief's format.
  - — [Creatify technical report](https://d35ghwdno3nak3.cloudfront.net/videoadagent_bench/v1/research-creatify-agent.html) (vendor, self-reported)
- **ViMax (HKUDS)** runs these stages:
  - An idea becomes a screenplay. A categorization step routes each input to a category-specific prompt.
  - Shot planning gives each shot a camera angle, movement, lighting, character positions, duration, sound and dialogue.
  - **Key images come first** (character profiles, backgrounds, shot keyframes).
  - Each shot's video is then conditioned on its keyframes.
  - A VLM picks the best of k candidates.
  - — [ViMax paper, arXiv 2606.07649](https://arxiv.org/html/2606.07649v1)
- **MAViS** has agents for script writing, shot design, character modeling, keyframe generation, video animation and **audio**. — [MAViS, arXiv 2508.08487](https://arxiv.org/abs/2508.08487)
- **product-film-skill** (Claude Code + Remotion) runs seven steps:
  1. Discovery: design rules, tokens, components, logo and allowed claims.
  2. Interview.
  3. Brand kit and story. It writes `videos/BRAND.md` and a beat sheet, and reviews 3 style frames before building.
  4. Music: it measures the beat grid, cuts the song on bars and places SFX on peaks.
  5. Build: one composition where "every frame [is] a pure function of time".
  6. Review: stills at each handoff, contact sheets and a half-res draft.
  7. Final render: a 240 fps master with motion blur, delivered as a muted loop, a version with music, a WebM and a poster.
  - — [Rieranthony/product-film-skill](https://github.com/Rieranthony/product-film-skill)
- **digitalsamba/claude-code-video-toolkit** tracks a project lifecycle in `project.json`: "planning → assets → review → audio → editing → rendering → complete". The README says it "automatically reconciles intent (what you planned) with reality (what files exist)". — [GitHub](https://github.com/digitalsamba/claude-code-video-toolkit)
- **HyperFrames' default agent flow** starts from one line: "Using /hyperframes, make a 10-second product intro for https://example.com." For longer, story-driven films the agent first offers three storylines to choose from. — [HyperFrames quickstart](https://hyperframes.heygen.com/quickstart)

#### Brief, selling points and brand ingestion
- `npx hyperframes capture https://stripe.com` "pull[s] a real website into a working folder an agent can build from". The example output lists 12 screenshots, 45 assets, 15 sections and the font sohne-var. `--json` is available. — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- HyperFrames' prompting docs say to point the agent at a source of brand truth (a design spec, a site or a Figma file) instead of asking for "on-brand". — [HyperFrames docs index](https://hyperframes.heygen.com/_llms/docs.txt)
- **Co-Director** (Google) takes four inputs per ad: brand identity, product reference, targeting strategy and a semantic prompt. Its constraints are brand fidelity, demographics and tight runtimes. — [Co-Director project page, arXiv 2604.24842](https://co-director-agent.github.io/)

#### Hook, script and storyboard
- Co-Director splits a creative configuration into three axes: **Creative Strategy** (the message), **Narrative Mode** (the delivery) and **Aesthetic Archetype** (the look, e.g. "Clarity/Energy", "Cinematic Premium", "Minimalist Focus", "Kinetic Grit"). A multi-armed bandit picks configurations, and a local multimodal self-refinement loop audits the output. — [Co-Director](https://co-director-agent.github.io/)
- **AgenticGen** (TikTok ads) splits ad video generation into two trainable stages, **strategy selection** and **draft generation**. — [arXiv 2609.09187](https://arxiv.org/abs/2609.09187)
- HyperFrames treats storyboard beats as timed elements (`data-beat="name"`). `snapshot --review` captures:
  - each scene at start+0.3 s and at its middle;
  - each beat at start+0.3 s;
  - "seams" from −0.2 to +0.2 s around every cut;
  - a set of frames at 360 px wide (phone width).
  - — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)

#### Keyframes and reference images for consistency
- **ViMax** keeps shots consistent in two ways:
  - A **dependency graph** links shots through shared characters, environments and objects. Independent shots run in parallel, and dependent shots are conditioned on the visuals of their prerequisite shots.
  - A **camera graph** generates transition videos between camera angles.
  - **Best-of-2** VLM selection gave the strongest consistency; best-of-3 and best-of-4 added nothing.
  - Removing the cross-shot dependencies lowered global consistency (GC) by 8.7%. Removing VLM selection lowered it by 3.8%.
  - — [ViMax paper](https://arxiv.org/html/2606.07649v1)
  - In the README, `image_selection.num_candidates` generates 2 keyframe candidates in parallel and lets a vision-capable chat model pick one. Set it to 1 to save API cost. — [HKUDS/ViMax](https://github.com/HKUDS/ViMax)
- **Product and logo shots**, per a vendor blog:
  - Approve a still first: front-facing or a slight three-quarter view, at least 1080×1080, on a plain background.
  - Keep rotation to 15° or less, and prompt for light, steam or camera movement instead of spinning the product.
  - Use reference images where supported. Veo 3.1 accepts up to 3 reference images, but only for 8 s clips.
  - Generate 4–6 takes and check frame 1, frames 5–10 and the last frame.
  - Verify with a contact sheet of the logo crop and SSIM against the first frame.
  - — [laozhang.ai blog](https://blog.laozhang.ai/en/posts/fix-logo-distortion-ai-product-video.md) (vendor)

#### Motion: generative model limits that constrain shot planning
- **Veo 3.1**: 4, 6 or 8 s per generation. Reference-image and first+last-frame modes are locked to 8 s. "Extend" adds 8 s, using the final frame as the anchor. Up to 3 reference images; no video or audio references. — [Atlas Cloud guide](https://www.atlascloud.ai/blog/guides/veo-3.1-length-limit-max-duration-guide), [fal.ai comparison](https://fal.ai/learn/tools/seedance-2-0-vs-veo-3-1) (secondary)
- **Seedance 2.0**:
  - Any whole number of seconds from 4 to 15.
  - Multimodal references: up to 9 images, 3 videos and 3 audio clips, 15 items in total.
  - One provider says strict first/last-frame mode can't be combined with multimodal references.
  - — [fal.ai](https://fal.ai/learn/tools/seedance-2-0-vs-veo-3-1) (secondary)
- **Kling 3.0**:
  - Clips up to 15 s (Kling 2.6 allowed 10 s).
  - Multi-shot generation, including "Custom Multi-Shot" with content and duration set per shot.
  - Native audio in Chinese, English, Japanese, Korean and Spanish.
  - Subject binding for consistency; the Omni variant adds video character references.
  - — [Kling 3.0 user guide](https://kling.ai/quickstart/klingai-video-3-model-user-guide); [gaga.art](https://gaga.art/blog/kling-3-0/) and [PiAPI](https://piapi.ai/kling-3-omni) report up to 6 cuts per generation (secondary)
- **Grok Imagine video API**: logged as launched on 2026-10-18. Clips are 1–15 s at 480p–1080p, priced at $0.02–$0.25/s on `/v1/videos`. — [APIYI launch log](https://docs.apiyi.com/en/live/2026-10/grok-imagine-official-launch.md); [Developers Digest](https://www.developersdigest.tech/models/video-generation/xai) (secondary)
- **HeyGen Video 1** generates "an AI video clip up to a minute long" inside HyperFrames Studio. — [HyperFrames docs index](https://hyperframes.heygen.com/_llms/docs.txt)
- **The Sora 2 API and Videos API** were scheduled to shut down on 2026-09-24 (announced 2026-03-24). Calls reportedly now return 410 Gone. — [Spheron](https://www.spheron.network/blog/sora-2-api-shutdown-2026-self-hosted-video-alternatives/), [Zilliz](https://zilliz.com/ai-faq/what-is-the-sora-shutdown-timeline) (secondary; consistent with each other)

#### TTS with timing
- **ElevenLabs** `POST /v1/text-to-speech/{voice_id}/with-timestamps` returns `audio_base64` plus `alignment` and `normalized_alignment`. Each alignment has `characters`, `character_start_times_seconds` and `character_end_times_seconds`. Timing is **character-level**, so word timings must be derived from it. `previous_text`/`next_text` and `previous_request_ids`/`next_request_ids` keep separately generated lines continuous. — [ElevenLabs API docs](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps)
- **HyperFrames `tts`** runs Kokoro-82M locally: "No API key, nothing leaves the machine". The first letter of the voice ID sets the language (a = American, b = British, e = Spanish, f = French, h = Hindi, i = Italian, j = Japanese, p = Brazilian Portuguese, **z = Mandarin**). Flags include `--speed` and `--json`. The docs' tip: "To get narration *and* caption timing in one pass: generate the audio with `tts`, then run `transcribe` on the result." — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **MoneyPrinterTurbo**:
  - TTS engines: Edge TTS (free, no key), Azure, SiliconFlow, Gemini, MiMo, MiniMax, ElevenLabs, Chatterbox, Kokoro, Fish Audio and VoxCPM.
  - Subtitle timing modes: `subtitle_provider = "edge"` uses TTS timestamps (fast, no GPU, the default). `"whisper"` uses local faster-whisper, which is more accurate; `large-v3` is about 3 GB and `large-v3-turbo` about 1.6 GB.
  - — [harry0703/MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo)
- **NarratoAI** TTS: Tencent Cloud, Doubao, IndexTTS-1.5/2 (voice cloning) and OmniVoice. — [linyqh/NarratoAI](https://github.com/linyqh/NarratoAI)

#### Music and sound
- **ElevenLabs Music API** is `POST https://api.elevenlabs.io/v1/music`:
  - It needs a paid plan. Output is "available for broad commercial use on all paid plans"; film, TV and large games need Enterprise.
  - Sources disagree on the model ID (`music_v1` vs `music_v2`).
  - — [ElevenLabs Music API](https://elevenlabs.io/music-api)
- **HyperFrames audio**:
  - Free tier: your own tracks or local generation, a bundled SFX set plus Openverse, and Kokoro voices. With HeyGen: a 10,000-track catalog and cloned voices. — [HyperFrames voice and audio guide](https://hyperframes.heygen.com/guides/voice-and-audio.md)
  - `<audio ... loop>` fills a slot. The audio-effects reference covers "the voiceover carve" and audio groups. — [same guide](https://hyperframes.heygen.com/guides/voice-and-audio.md); [docs index](https://hyperframes.heygen.com/_llms/docs.txt)
  - `npx hyperframes beats <file> --json` returns `{ ok, file, count, bpm, beatTimes }`.
  - `normalize-audio` matches clip loudness using "FFmpeg's integrated EBU R128 loudness measurement". — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **FFmpeg ducking** example: `[bg][voice]sidechaincompress=threshold=0.02:ratio=8:attack=50:release=500[ducked]`, after normalizing both inputs with `aformat=fltp:44100:stereo`. — [FFmpeg cookbook: audio ducking](https://ffmpeg-cookbook.pages.dev/en/articles/audio-ducking/) (secondary; verify against ffmpeg-filters docs)
- **product-film-skill** builds a beat grid with `beats.py` (numpy) and cuts the song on bars with `audio-edit.py`. The README requires the user to own rights to the music. — [GitHub](https://github.com/Rieranthony/product-film-skill)

#### Captions with word-level timing
- **faster-whisper**:
  - Usage: `segments, _ = model.transcribe("audio.mp3", word_timestamps=True)`, then `for word in segment.words:` gives `.start`, `.end` and `.word`.
  - `vad_filter=True` uses Silero VAD, and `BatchedInferencePipeline(model=model)` runs batched.
  - Benchmark (13 min of audio, RTX 3070 Ti, large-v2): fp16 takes 1m03s; int8 with batch_size=8 takes 16 s.
  - The CPU small model in int8 takes 1m42s.
  - It needs CUDA 12 and cuDNN 9.
  - **WhisperX** is listed as a community integration that produces word-level timestamps via wav2vec2 alignment.
  - — [SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)
- **Remotion captions**:
  - `toCaptions({whisperCppOutput})` from `@remotion/install-whisper-cpp` (with `tokenLevelTimestamps: true`) produces `Caption {text, startMs, endMs, timestampMs, confidence}`. — [Remotion toCaptions](https://www.remotion.dev/docs/install-whisper-cpp/to-captions)
  - `createTikTokStyleCaptions({captions, combineTokensWithinMilliseconds: 1200})` returns `pages[]`, each with `text`, `startMs`, `durationMs` and `tokens[{text, fromMs, toMs}]`. `breakOnSilenceAfterMilliseconds` starts new pages on gaps. — [Remotion createTikTokStyleCaptions](https://www.remotion.dev/docs/captions/create-tiktok-style-captions)
- **HyperFrames `transcribe`**:
  - Engines: Parakeet TDT 0.6B v3 (25 European languages) or whisper.cpp (default model `small.en`).
  - It imports whisper.cpp JSON, OpenAI Whisper JSON, SRT and VTT, and normalizes all of them to `transcript.json` = `[{text, start, end}]`.
  - `--to srt|vtt` exports a sidecar file. `--preserve-cues` keeps cues as-is for "single-word or CJK captions".
  - The docs' tip: "For production content, transcribe through the OpenAI or Groq Whisper API and import the JSON."
  - — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **Caption craft rules**: check names, product terms and numbers, which is "where recognition slips". Keep lines short and broken on meaning, keep them off faces and buttons, and emphasize the 2–3 key words. — [HyperFrames voice and audio guide](https://hyperframes.heygen.com/guides/voice-and-audio.md)

#### Assembly and rendering
- **HyperFrames**:
  - A composition is plain HTML. Timing lives in data attributes: `data-composition-id`, `data-start`, `data-duration`, `data-track-index`, `data-width`, `data-height` and `data-volume`.
  - Animation is a **paused** GSAP timeline registered on `window.__timelines`. Adapters exist for GSAP, CSS, Lottie, Three.js, Anime.js, WAAPI and custom frame code.
  - Rendering seeks each frame in headless Chrome, then FFmpeg encodes the frames.
  - Requirements and license: Node.js 22+ and FFmpeg; Apache-2.0.
  - The catalog has about 450 blocks, and there are AWS Lambda and Cloud Run rendering paths.
  - — [heygen-com/hyperframes README](https://github.com/heygen-com/hyperframes)
  - Render flags:
    - `--docker` renders "for deterministic output".
    - `--workers` takes 1–24; each worker is "a separate Chrome, roughly 256 MB".
    - `--format` takes mp4, webm (VP9 with alpha), mov (ProRes 4444), gif, png-sequence or hls.
    - `--quality` takes draft, looks (CRF 16, the default) or delivery.
    - `--fps` takes 1–240.
    - `doctor` diagnoses the machine.
    - — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **HyperFrames determinism contract**:
  - `time = floor(frame) / fps`.
  - No `Date.now()`, no `requestAnimationFrame`, no system timers, no unseeded `Math.random()` and no fetching mid-render. Output size is fixed before frame 0.
  - Chrome's `HeadlessExperimental.beginFrame` captures each frame atomically, and FFmpeg mixes in the audio from `<audio>` and `<video>` elements.
  - — [HyperFrames determinism](https://hyperframes.heygen.com/concepts/determinism.md)
- **Remotion**:
  - Videos are React components. `calculateMetadata` (which may be async) returns `durationInFrames`, `width`, `height`, `fps`, `props`, `defaultOutName` and `defaultCodec`. Returned values override the `<Composition>` values, so duration can come from data. — [Remotion calculateMetadata](https://www.remotion.dev/docs/calculate-metadata)
  - Render a video with `npx remotion render <entry-point> <composition-id> <output>`. Render several stills with `npx remotion render MyComp out/frames --frames=0,30,90 --image-format=png` (v4.0.502+). — [Remotion still CLI](https://www.remotion.dev/docs/cli/still)
- **MoneyPrinterTurbo** outputs 9:16 at 1080×1920, 16:9 at 1920×1080 and 1:1 at 1080×1080. FFmpeg is located automatically or set via `ffmpeg_path` / `IMAGEIO_FFMPEG_EXE`. — [GitHub](https://github.com/harry0703/MoneyPrinterTurbo)

#### Automated QA
- **HyperFrames QA commands**:
  - `npx hyperframes lint [dir] --json` reads the HTML without a browser and returns `errorCount`, `warningCount` and `findings`. Errors must be fixed before rendering.
  - `npx hyperframes check [dir] --json` is "the browser gate". It sweeps a seek grid and reports:
    - runtime console errors and failed requests;
    - **layout defects**: overflow, clipping, held overlaps, occlusion and coordinate-frame drift;
    - `*.motion.json` assertions;
    - **WCAG AA contrast** and "craft" warnings;
    - **audio**: a source with no or unreadable audio is an error; a clip that starts past the end of its file and a silent played portion are warnings; a film with no sound at all is info.
  - The JSON sections are `{ok, browserSkipped, scope, lint, runtime, layout, motion, contrast, craft, audio, hdr, snapshots}`.
  - `snapshot` options:
    - `--at 2.9,10.4`, or `--frames N` for evenly spaced frames.
    - `--zoom '#headline'` crops to a selector.
    - `--against ref.mp4` saves the matching reference frames and labelled render/reference pairs.
    - `--review` produces the beats, seams and phone contact sheets.
    - `--describe` sends the frames to Gemini.
  - — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md); [CLI guide](https://hyperframes.heygen.com/developers/cli.md)
- **HyperFrames harness hook**: an agent harness sets `HF_TOOL_CONTEXT`, for example `{"version":1,"capabilities":{"events":{"transport":{"type":"ndjson-file","path":...}},"project-lock":{"waitMs":90000}}}`.
  - The CLI then appends `artifact.created` events whose roles are `frame`, `contact-sheet`, `check-report` or `finding`.
  - `project-lock` makes browser commands run one at a time.
  - `check-review: {findingFrames, inspect}` attaches a full frame to each layout or contrast finding, plus the source snippets (`file:start-end`) of the offending element.
  - — [HyperFrames: running the CLI from an agent harness](https://hyperframes.heygen.com/developers/harness-tool-context.md)
- **Sync and regression checks**: `measure sync` reports the lag between mouth motion and voice. `diff original.mp4 final.mp4` scores SSIM, the worst moments, missed and extra cuts, duration and sound offset, and exits non-zero below its thresholds (`--min-mean`, `--min-p05`). `compare v1/ v2/` renders variants side by side. — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **Creatify's frame-level hallucination rubric** scores product fidelity, object hallucination, text quality, physical violations, anatomy and overall quality on 0–10 (lower is better); **≥3.0 is a production-grade FAIL**. Known miss: "minor brand-text wobble or inter-cut inconsistencies the critic misses". — [Creatify report](https://d35ghwdno3nak3.cloudfront.net/videoadagent_bench/v1/research-creatify-agent.html)
- **Code2Video** uses a Planner, a Coder (writes Manim code, with auto-fix) and a Critic. The Critic gives the VLM a **6×6 grid of visual anchors**, so its spatial feedback maps directly to code coordinates. — [arXiv 2510.01174](https://arxiv.org/abs/2510.01174); details via [Emergent Mind summary](https://www.emergentmind.com/papers/2510.01174) (secondary)
- **FFmpeg signal QA**: run each filter with `-f null -` and grep stderr, e.g. `ffmpeg -i "$INPUT" -vf "blackdetect=d=0.5" -f null - 2>&1 | grep blackdetect`.
  - Frozen frames: `freezedetect=n=0.003:d=2`.
  - Silence: `silencedetect=noise=<dB>:d=<s>`.
  - Loudness: `ebur128=metadata=1`, adding `peak=true` for true peak.
  - Video filters and audio filters need separate passes or a combined filtergraph.
  - — [ffmpeg video-analysis skill (skills.lc)](https://www.skills.lc/JosiahSiegel/claude-plugin-marketplace/josiahsiegel-claude-plugin-marketplace-plugins-ffmpeg-master-skills-ffmpeg-video-analysis-skill-md); [ez-ffmpeg detector source](https://docs.rs/crate/ez-ffmpeg/latest/source/src/core/analysis/detector.rs) (secondary; check with `ffmpeg -h filter=<name>`)
- **product-film-skill `verify.py`** decodes the outputs and checks "colors, duration and a seamless loop". — [GitHub](https://github.com/Rieranthony/product-film-skill)
- **Claude vision limits that shape frame-sampling QA**:
  - Supported formats are JPEG, PNG, GIF and WebP. "Animations are unsupported, and only the first frame is used."
  - Up to **600 images per API request** (100 for models with a 200k-token context window) and 20 per turn on claude.ai.
  - With **more than 20 images**, a stricter per-image limit applies; keep each image at 3,000 px or less.
  - 10 MB per image and 128 MB per request.
  - Cost is `⌈w/28⌉×⌈h/28⌉` visual tokens.
  - The high-resolution tier (Claude 4.7 and later) allows a 2,576 px long edge and 4,784 tokens. A 1920×1080 frame costs 2,691 tokens on that tier and 1,560 on the standard tier.
  - At Opus 5.5's $4/M input tokens, 1,000 images of 1000×1000 cost about $5.18.
  - Stated limitations: localization is approximate, counting is approximate, and Claude "cannot determine whether an image is AI-generated".
  - — [Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)

#### Variants
- **HyperFrames variables**:
  - Declared with `data-composition-variables`. Types are `string`, `number`, `color`, `boolean`, `enum`, `font` and `image`. The `portrays` field marks identity slots that must not be filled with invented copy. — [HyperFrames variables](https://hyperframes.heygen.com/concepts/variables.md)
  - Rendering takes `--variables '{"title":"Q4 Report"}'` or `--variables-file`. `--batch` renders "one output per variables row". `--batch-concurrency` and `--batch-fail-fast` control batches. There is also "Render templates on Lambda" from JSONL. — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md); [docs index](https://hyperframes.heygen.com/_llms/docs.txt)
- **MoneyPrinterTurbo** `cli.py --batch-file` takes a JSON array or JSONL file of up to 100 tasks (1 MiB). Every entry is validated before the first task runs, a failed task doesn't stop the rest, and a JSON summary prints at the end. — [GitHub](https://github.com/harry0703/MoneyPrinterTurbo)
- **Co-Director**'s bandit optimization (T=4) reached an average MLLM-judge score of 81.4, against 75.7 for random search at T=4. — [Co-Director](https://co-director-agent.github.io/)
- **AgenticGen**, after DPO and GRPO, beat its SFT baseline in online TikTok A/B tests: **CTR +2.72%, CVR +2.63%, Advv +9.61%**. — [arXiv 2609.09187](https://arxiv.org/abs/2609.09187)

### Inferences
- **Proposed stage graph for the Agent SDK demo.** Each stage writes one artifact into the project folder, so a later turn can resume or redo it alone.
  1. `brief.json` is normalized from chat. Defaults: platform, 9:16, 30 s, language. Ask at most one or two clarifying questions, the way HyperFrames offers three storylines and product-film-skill reviews three style frames.
  2. `brand.json` and `selling_points.json`, built from `hyperframes capture <url>` or user uploads. Each claim carries its evidence source, and banned claims are listed.
  3. `script.json` holds 2–3 hook variants plus a beat sheet with target durations.
  4. `shots[]` in `project.json` gives each shot `kind: code | gen | stock | avatar` and a duration snapped to what the generator allows: Veo 4/6/8 s; Seedance whole seconds 4–15; Kling up to 15; Grok 1–15.
  5. Reference stills for gen shots, approved with VLM best-of-2.
  6. Per-shot motion. Code shots become HTML/React compositions. Gen shots become I2V jobs fanned out in parallel along ViMax-style dependencies.
  7. Voiceover generated **per line or per shot**, so editing one line regenerates one file.
  8. Music: beats → snap cuts to the beat grid → duck under the voice.
  9. Captions from TTS alignment, or from `transcribe` run on the TTS output.
  10. Assembly. Gen clips are just `<video>` elements on tracks.
  11. QA ladder: lint → check → `snapshot --review` contact sheets → Claude vision rubric → FFmpeg black/freeze/silence/EBU R128 checks on the final MP4.
  12. Variants via `--batch` or Remotion inputProps.
- **Let the voiceover drive timing.** Generate TTS first, measure it, then set shot durations (`data-duration`, or Remotion `calculateMetadata`). Don't guess words-per-second. Gen-clip durations are quantized, so over-generate slightly and trim during assembly.
- **Chinese captions.** Chinese has no spaces, so word-level grouping needs segmentation. ElevenLabs' character-level timings group naturally into CJK cues, and HyperFrames has `--preserve-cues` for this case. Note that Parakeet doesn't cover Chinese, so `transcribe` falls back to whisper for zh.
- **Send contact sheets, not raw frames.** A 4×4 sheet at ≤2,576 px costs about 4.8k tokens on Opus 5.5's high-res tier. That reviews a 30 s ad in 1–3 images, stays under the 20-image threshold, and costs well under $0.10 per QA pass.

## Q2. How should a project be represented so edits are cheap and partial, and how should it be versioned?

### Takeaway
Keep one typed, declarative project document (shot list and timeline JSON) as the source of truth. Compile it into a deterministic render target: HyperFrames HTML with data attributes and variables, or a Remotion composition with inputProps. Store generated media by content hash, so an edit only regenerates the nodes it invalidates, and record each chat turn as a version. HyperFrames already ships most of the needed primitives:
- `timeline --json` with move/trim/split/set/delete verbs and `--plan` diffs;
- `history begin/end/undo --who claude` for per-agent turns;
- variables, and override deltas against a base template;
- `compare` and `diff` for visual regression.

OTIO and EDL work well as interchange and export formats, but not as the authoring format.

### Cited Findings
- HyperFrames says it has "No React requirement, no proprietary timeline format". Clip timing lives in HTML data attributes, and `index.html` "plays as-is" with no build step. — [hyperframes README](https://github.com/heygen-com/hyperframes)
- **Timeline as agent-editable data.** `npx hyperframes timeline --json` prints every track and clip with its start, duration, file and track. Edit verbs write to the file that holds the clip:
  ```
  npx hyperframes timeline move '#outro' +1 --plan   # show the result and diff, write nothing
  npx hyperframes timeline move '#outro' after:#intro
  npx hyperframes timeline trim '#intro' --duration 2
  npx hyperframes timeline split '#outro' 6.5
  npx hyperframes timeline set '#music' volume=0.5
  npx hyperframes timeline delete '#outro' --start 6 --end 7
  ```
  Time values accept "seconds, relative offsets, frames, and anchors such as `after:#intro`". — [HyperFrames CLI guide](https://hyperframes.heygen.com/developers/cli.md); [CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **Turn-level version history.**
  - `history begin --who claude --label "Bigger title"` … `history end` records "one entry under your name".
  - `undo --who claude` undoes that agent's newest turn and refuses rather than undoing an older one.
  - `restore`, `peek`, `pin` and `show <ref> --diff` are also available.
  - Data is stored under `~/.cache/hyperframes/history`, or `HYPERFRAMES_HISTORY_ROOT` "which keeps an agent run or a test apart".
  - — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **Variables vs structural edits.** "Use a variable when the design should remain stable across versions. Make a normal source edit when the structure itself needs to change." Example declaration: `data-composition-variables='[{"id":"title","type":"string","label":"Title","default":"Pro"},{"id":"accent","type":"color",...}]'`. — [HyperFrames variables](https://hyperframes.heygen.com/concepts/variables.md)
- **Sparse deltas over a base template ("Embedded Override Mode").**
  - You "maintain one base composition HTML file and store only the per-instance *delta* (the `OverrideSet`)".
  - Keys follow `hfId.prop.path`, e.g. `{"hf-title.text": "Acme Corp Launch", "hf-logo.attr.src": "/customers/acme/logo.png", "hf-subtitle.style.color": "#0EA5E9"}`.
  - The API is `openComposition(templateHtml, {overrides, history:false})`, then `comp.setText(...)`, `comp.getOverrides()`. Elements added with `addElement()` are stored in the delta too.
  - — [HyperFrames SDK: embedded override mode](https://hyperframes.heygen.com/sdk/guides/embedded-override-mode.md)
- **The composition file is the reproducible artifact.** "Renders are deterministic, so re-rendering that file reproduces the result." — [HyperFrames: recreating references](https://hyperframes.heygen.com/prompting/recreating-references.md); [determinism](https://hyperframes.heygen.com/concepts/determinism.md)
- **Remotion parametrization.**
  - `calculateMetadata` receives `{props, defaultProps, abortSignal, compositionId, isRendering}` and can be async. It returns metadata and transformed `props`, which must be JSON-serializable (only `Date`, `Map`, `Set` and `staticFile()` are allowed beyond JSON).
  - It runs once per render in a separate tab during `selectComposition()`, and re-runs whenever props change in Studio.
  - — [Remotion calculateMetadata](https://www.remotion.dev/docs/calculate-metadata)
  - Remotion's agent skills include `/remotion-interactivity` ("Makes code editable in Studio") and `/remotion-saas` (architecture for Remotion-powered apps). — [Remotion agent skills](https://www.remotion.dev/docs/ai/skills)
- **OpenTimelineIO (OTIO)**:
  - An open-source API and interchange format for editorial timelines, under the Academy Software Foundation.
  - It serializes to JSON: a tree of Timeline → Stack/Track → Clip, using the `.otio` extension.
  - The spec recommends reading and writing it through the library (`pip install opentimelineio`), with adapters such as AAF, rather than hand-writing JSON.
  - — [OTIO GitHub](https://github.com/AcademySoftwareFoundation/OpenTimelineIO); [OTIO file format spec](https://opentimelineio.readthedocs.io/en/v0.12/tutorials/otio-file-format-specification.html)
- **PySceneDetect** can export detected cuts as OTIO (`save-otio`, Timeline.1 schema, audio included unless `--no-audio`) or as CMX 3600 EDL (`save-edl`). — [PySceneDetect CLI docs](https://www.scenedetect.com/docs/latest/cli.html)
- **NarratoAI's "common script format"**:
  - An `items` array where each item has `_id` (a positive integer), `timestamp` (strict `HH:MM:SS,mmm-HH:MM:SS,mmm`), `picture` (a description), `narration` and `OST` ∈ {0, 1, 2}. OST 0 = narration only, 1 = keep the original audio, 2 = mix both.

These **conflict**. — [zread overview](https://zread.ai/linyqh/NarratoAI/1-overview); [README](https://github.com/linyqh/NarratoAI)
- **Creatify's typed asset graph** (product facts, persona, brand state, required on-screen text) is both the generation spec and the critic's rubric. Failed scenes are regenerated locally. — [Creatify report](https://d35ghwdno3nak3.cloudfront.net/videoadagent_bench/v1/research-creatify-agent.html)

- **Content addressing makes edits partial.** Key every generated asset by `sha256(provider|model|mode|prompt|refs|seed|params)` for video, and `sha256(voice|text|model|settings)` for TTS. When the agent applies a JSON Patch, a dirty-checker regenerates only the nodes whose keys changed:
  - Changing a caption style regenerates nothing and only re-renders.
  - Changing one VO line regenerates one TTS segment and its word timings, and may ripple the shot starts after it.
  - Changing a gen-shot prompt re-queues only that shot.
- **Versioning.** Snapshot `project.json` each turn (v1, v2, …), and use git for compositions and code. Keep a per-turn JSON-Patch op log, which doubles as trajectory logging for the project's rubric. Key renders by the hash of the compiled composition plus its assets. With HyperFrames, wrap each agent turn in `history begin/end --who claude` and use `compare v6/ v7/` to show the user what changed.
- **Mapping to the project's flows.**
  - Flow 2 (requirement changes → new versions): a new version branch, with old versions still renderable.
  - Flow 3 (subtitle edits): edit ops on the caption track and overlays. No generative calls.
  - Flow 4 (imitate a reference): `template.json` from reference analysis (Q4), instantiated with this brand's variables.
- **Where OTIO fits.** Use it as an export to NLEs (DaVinci, Premiere) and to ingest PySceneDetect cut lists. It has no animation semantics, so it can't be the authoring format for motion-graphics shots.

## Q3. When should an agent choose programmatic animation and when generative video? (heuristics, hybrids, cost, latency, licensing)

### Takeaway
Route each shot by asking whether it **must be exact** or **must look real**:
- **Code path.** Anything that carries words, numbers, UI, product cards, prices, logos, legal claims or captions. It's deterministic, editable at near-zero marginal cost, and re-renders identically.
- **Image-to-video from an approved still.** Photoreal people, places, the physical product in use, and camera moves through real space.
- **Hybrid, for most ads.** Text-free generated plates with code overlays, plus a code end card. Current video models still distort text and logos. They cost about $0.02–$0.60 per second, take minutes per clip, and need several takes per usable shot.

The project's two benchmarks map onto these paths. Claude Motion (Anthropic, beta October 2026) is explicitly code-only with no video model; Grok Imagine is a generative API. Sora 2's API has been retired, so it shouldn't be a build target.

### Cited Findings

#### Where generative video fails (evidence for routing text and brand to code)
- "On-screen text warps, letters shift, and logos distort", because text "requires pixel-perfect consistency, which conflicts with how diffusion models generate imagery". Image-to-video models "move pixels from frame to frame. They have no idea that a group of pixels is a trademark."   - **Regenerate** when the product itself drifts (outline, proportions, colors).
  - **Hold a clean frame or shorten** when the logo fails only at the end.

  - **Composite the real logo** when the letters must match the artwork in every readable frame: one FFmpeg overlay on a locked shot, or a planar track on a moving camera.

## Q4. How should a viral reference ad be analyzed for "cloning" (scene detection, ASR, frame captioning, template extraction), given that Claude only takes images?

### Takeaway
Claude can't watch video: it accepts JPEG, PNG, GIF and WebP, and uses only the first frame of an animation. So "watching" a reference means:
1. Deterministic decomposition: probe → cut detection → keyframes and contact sheets per shot → ASR word timings → audio beats and loudness → look, color and motion energy.
2. Claude vision on the sampled frames.
3. Distilling the results into a reusable template with absolute values: hook, beat and shot timings, shot types, camera language, text cadence, music BPM.

Rebuild from the template with the user's brand swapped in, then verify against the reference with frame-paired comparison. HyperFrames now ships this toolchain (`measure`, `snapshot --against`, `diff`, plus a `reverse-any-video` skill). It reports that a text-only motion transcription one-shots about 75% of the target and plateaus around 90% after iteration.

### Cited Findings
- **Input constraint**: "Claude supports JPEG, PNG, GIF, and WebP images … Animations are unsupported, and only the first frame is used." The request limits and token costs are in Q1. — [Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)
- **PySceneDetect CLI**:
  - **Detectors and defaults**:
    - `detect-content`: threshold 27.0, the default for fast cuts.
    - `detect-adaptive`: threshold 3.0, min-content-val 15.0, frame window 2, two-pass rolling average.
    - `detect-threshold`: threshold 12.0, for fades.
    - `detect-hash`: threshold 0.395, perceptual hashing.
    - `detect-hist`: threshold 0.05, YUV histograms.
    - The global minimum scene length is 0.6 s.
  - **Outputs**:
    - `list-scenes` writes `$VIDEO_NAME-Scenes.csv`.
    - `save-images --num-images 5` saves stills (default 3 per scene; `--width 1024`).
    - `split-video` (x264 CRF 22; `--copy` is faster).
    - `save-edl`, `save-otio`, `save-html` and `save-qp`.
  - Example: `scenedetect -i video.mp4 detect-adaptive --threshold 3.2`.
  - — [PySceneDetect CLI docs](https://www.scenedetect.com/docs/latest/cli.html)
- **FFmpeg scene detection**:
  - The usual pattern is `select='gt(scene,0.4)'` with `showinfo`, plus `-vsync vfr` (`-fps_mode` in newer builds) and a numbered image pattern to dump one frame per change.
  - "Sane values are typically between 0.3 and 0.5."
  - `select=scene+1` passes every frame through, so `lavfi.scene_score` can be read for all of them.
  - The `scdet` filter is an alternative; GDELT used `s=1`, `t=14`.
  - — [jdhao keyframe guide](https://jdhao.github.io/2021/12/25/ffmpeg-extract-key-frame-video); [FFmpeg-user list](https://lists.ffmpeg.org/pipermail/ffmpeg-user/2012-November/011101.html); [GDELT blog](https://blog.gdeltproject.org/using-ffmpegs-scene-detection-to-generate-a-visual-shot-summary-of-television-news/); [gist](https://gist.github.com/dudewheresmycode/054c8de34762091b43530af248b369e7)
- **HyperFrames reverse-engineering commands**, which "serve the `reverse-any-video` skill: measure a video, have HeyGen draft its timeline, then score your rebuild against it". `npx hyperframes measure <sub> ref.mp4` has these subcommands:
  - `probe`: size, frame rate, duration and sound.
  - `cuts`: hard cuts and the shots between them.
  - `events`: cuts, flashes, appears, disappears and holds; `--map` adds the sound's hits.
  - `frames`: overview sheets and strips around events.
  - `extract`: a still or clip as project media.
  - `curve`: each move of one element, with start, duration, overshoot and "the closest GSAP ease".
  - `energy`: how much two clips move, and whether at the same moments.
  - `look`: brightness, contrast, saturation and warmth.
  - `face`: the face's size and position over a window.
  - `sync`: the lag between mouth motion and voice.

  `snapshot --at … --against ref.mp4` saves frame-exact reference frames and labelled pairs. `diff original.mp4 final.mp4 --segments segments.md --sbs` scores SSIM, missed and extra cuts, duration and sound offset per segment, and exits non-zero below its thresholds. — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **HyperFrames' measured guidance for recreating a reference**:
  - Watch it frame by frame and write down "the exact duration, the camera's path, what each element does, with timestamps, how entrances overlap, which layers are blurred, sampled colors". A prompt built this way "one-shots about 75% of the target".
  - Iterate with **absolute targets**, e.g. "`dot radius = 25% of row spacing`", not "`make dots 2x finer`". "Relative corrections pendulum".
  - Distill the converged constants back into the prompt: this "one-shots ~80–90% of the converged quality". "From text alone, you can reach roughly 90% of a reference … That last 10% doesn't close from text."
  - — [HyperFrames: recreating references](https://hyperframes.heygen.com/prompting/recreating-references.md)
- **HyperFrames Studio's reference flow** (product UX worth copying):
  - Accepts one public URL from YouTube, TikTok, Instagram or X (up to 30 min), or an uploaded file.
  - It classifies the video: talking-head becomes "**Copy editing style**" (cuts, captions and effects, with your footage or an avatar); graphics with nobody on camera becomes a "**Video brief**".
  - It shows "**What to swap**" with time ranges, e.g. "Your opening question 0:00-0:02" and "Your website URL 0:02-0:05". Each slot can be agent-filled, typed, uploaded or generated (with the price shown).
  - "Show original" overlays the reference, then shows it side by side on one clock.
  - It uses the HeyGen API balance.
  - — [HyperFrames: reference any video](https://hyperframes.heygen.com/studio-app/reference-video.md)
- **Creatify's reference-video decomposition** extracts "shot rhythm, color, camera language, transitions, and on-screen-text cadence to ground the scene plan". — [Creatify report](https://d35ghwdno3nak3.cloudfront.net/videoadagent_bench/v1/research-creatify-agent.html)
- **NarratoAI's documentary mode** is "a two-phase vision-to-narration pipeline": frame extraction → batched vision analysis to Markdown → a text LLM writes the narration → parsed into timed script items with OST flags. `generate_script()` takes the frame interval, the vision batch size and `vision_llm_provider`. Vision backends: Qwen2-VL, TwelveLabs Pegasus (`vision_llm_provider = "twelvelabs"`), and Gemini (topic tag only). — [zread: documentary frame analysis](https://zread.ai/linyqh/NarratoAI/23-documentary-frame-analysis); [zread: script generation flow](https://zread.ai/linyqh/NarratoAI/9-script-generation-flow); [README](https://github.com/linyqh/NarratoAI)
- **ASR**: faster-whisper with `word_timestamps=True`, plus `vad_filter=True` with custom `vad_parameters=dict(min_silence_duration_ms=500)`; WhisperX for wav2vec2-aligned words. — [faster-whisper](https://github.com/SYSTRAN/faster-whisper). HyperFrames `transcribe video.mp4 --model medium.en` is "noticeably more accurate" for music or noisy audio. — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **Optional video-native captioning**: `hyperframes snapshot --describe` sends frames to Gemini (it needs `GEMINI_API_KEY`). — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)
- **Music analysis**: `npx hyperframes beats ref.mp4 --json` returns `bpm` and `beatTimes` without writing anything. — [HyperFrames CLI reference](https://hyperframes.heygen.com/packages/cli.md)

### Inferences
- **Concrete reference-analysis pipeline for the demo** (all Linux CLI; Claude only sees images and text):
  ```bash
  ffprobe -v error -show_streams -show_format -of json ref.mp4 > ref/probe.json
  scenedetect -i ref.mp4 detect-adaptive list-scenes save-images -n 3 --width 768 save-otio   # cuts + 3 stills/shot + OTIO
  #   (or: npx hyperframes measure cuts ref.mp4 --json ; measure events ref.mp4 --map --json)
  python -I asr.py ref.mp4 > ref/words.json      # faster-whisper word_timestamps=True, vad_filter=True
  npx hyperframes beats ref.mp4 --json > ref/beats.json
  npx hyperframes measure look ref.mp4 --json > ref/look.json
  # build 4x4 contact sheets per ~8 shots (ffmpeg tile filter or PIL), <=2576px long edge
  ```
  Then one Claude vision call per contact sheet, or per shot for the first 3 s (the hook), with a fixed JSON output schema per shot:
  - `shot_type` (close-up, packshot, UGC selfie, screen recording, text card, …);
  - `camera` (static, push-in, handheld, whip pan);
  - `on_screen_text` (verbatim plus position);
  - `subject`, `color/look` and `transition_in`;
  - `purpose` (hook, problem, demo, proof, offer, CTA).
- **Template output (`template.json`)**:
  - total duration, and the cut list with per-shot durations and a pacing histogram;
  - hook anatomy: words spoken in 0–3 s, text-on-screen timing, shot count in the first 3 s;
  - VO pace in words per second, measured from `words.json`;
  - caption style (lines, emphasis, position) and music BPM, with cuts snapped to beats or not;
  - beat structure, e.g. hook → pain → demo → proof → offer → CTA;
  - a "swap slots" list (brand name, product shots, claims, URL, people) with time ranges, as in HyperFrames Studio.

  Use absolute values throughout (seconds, hex colors, ratios), following HyperFrames' finding that relative instructions oscillate.
- **Verification.** After rendering the clone, run `hyperframes diff ref.mp4 out.mp4 --segments` for cut and timing agreement only. Low SSIM is expected and desired, because the content is swapped. Use `snapshot --against` pairs for Claude to judge structural similarity.
- **IP hygiene.** Clone the **structure** (timing, shot grammar, caption style), never the footage, music or brand marks of the reference. The "what to swap" step should force-replace every identity slot, which is what HyperFrames' `portrays` metadata is for.

## Q5. Which open-source implementations, agent frameworks and 2025–2026 papers exist, how are they built, and what can be reused?

### Takeaway
There are two families:
- **Multi-agent "film crew" research systems**: ViMax, MAViS, MovieAgent, AniMaker, Co-Director, VideoMemory, STAGE. They contribute hierarchical planning, shot dependency graphs, keyframes-first generation and VLM best-of-k selection. Mostly they lack audio, pacing control and interactive revision.
- **Practical assembly pipelines and code-video toolkits**: MoneyPrinterTurbo, NarratoAI and short-video-maker on one side; HyperFrames, Remotion skills, digitalsamba's toolkit, product-film-skill and Code2Video on the other. They contribute TTS, subtitles, assembly, variant batching and render-review loops.

For a Claude Agent SDK demo, the highest-leverage reuse is:
- the HyperFrames (or Remotion) **skills plus CLI**, loaded as filesystem SKILL.md;
- ViMax's planning and consistency ideas;
- Creatify's typed asset graph plus a per-scene critic;
- MoneyPrinterTurbo's and NarratoAI's script and subtitle schemas.

### Cited Findings

#### Agent SDK facts that determine how skills are reused
- Skills are filesystem artifacts (`.claude/skills/<name>/SKILL.md` or `~/.claude/skills/`). They load through `settingSources`/`setting_sources` (include `"user"` and `"project"`), and the `skills` option takes `"all"` or a list of names. "The SDK doesn't provide a programmatic API for registering them".
  - Sending `/<name>` dispatches a skill.
  - The `system/init` message lists the loaded skills.
  - The `plugins` option can load skills from a specific path.
  - `allowed-tools` frontmatter or `allowedTools` pre-approves tools.
  - — [Agent SDK skills docs](https://code.claude.com/docs/en/agent-sdk/skills)

#### Code-video toolkits (directly reusable as skills)
- **HyperFrames (HeyGen)**:
  - Apache-2.0; about 76.1k stars when captured.
  - Packages: `hyperframes` (CLI), `@hyperframes/core`, `engine` (Puppeteer + FFmpeg), `producer` (capture, encoding, audio mixing), `studio`, `player`, `shader-transitions` and `aws-lambda`.
  - Skills: `/hyperframes`, `/hyperframes-cli`, `/hyperframes-registry` and `/media-use`, plus on-demand `/figma`, `/slideshow` and `/remotion-to-hyperframes`.
  - Install with `npx skills add heygen-com/hyperframes --all`, or `claude plugin marketplace add heygen-com/hyperframes` then `claude plugin install hyperframes@hyperframes`.
  - — [GitHub](https://github.com/heygen-com/hyperframes)
  - The CLI is built for harnesses: `--json` output, `HF_TOOL_CONTEXT` events and project locks. — [harness doc](https://hyperframes.heygen.com/developers/harness-tool-context.md)
  - Its docs are LLM-indexed (`/llms.txt`, `/_llms/docs.txt`, 134 pages). — [docs index](https://hyperframes.heygen.com/_llms/docs.txt)
- **Remotion**: official skills (listed in Q3). Its docs are also agent-friendly: append `.md` to any docs URL, or send `Accept: text/markdown`. — [Remotion AI docs](https://www.remotion.dev/docs/ai); [skills](https://www.remotion.dev/docs/ai/skills)
- **digitalsamba/claude-code-video-toolkit** (MIT):
  - Skills: remotion, ffmpeg, moviepy, playwright-recording, elevenlabs, acestep (music), ideogram4, qwen-edit, ltx2, frontend-design and runpod.
  - Commands: `/video`, `/brand`, `/scene-review`, `/design`, `/generate-voiceover`, `/redub`, `/voice-clone`, `/thumbnail`, `/versions` and `/publish`.
  - Python tools run via `uv run`: voiceover, music_gen, sfx, flux2, ltx2, upscale, qwen3_tts, sadtalker and more.
  - Cloud GPU via Modal or RunPod.
  - — [GitHub](https://github.com/digitalsamba/claude-code-video-toolkit)
- **Rieranthony/product-film-skill**:
  - `SKILL.md` covers workflow, craft defaults and "traps".
  - `reference/` holds discovery, interview, ingredients, story, engine, music, review and render docs.
  - `templates/` holds `BRAND.md`, `film-prompt.md` and a `kit/` with a time grid, springs, camera, cursors, "magic moves", punchlines and a debug overlay.
  - `scripts/` holds `beats.py`, `audio-edit.py`, `stills.ts`, `render.ts` and `verify.py`.
  - — [GitHub](https://github.com/Rieranthony/product-film-skill)
- **gyoridavid/short-video-maker** (MIT, TypeScript):
  - Input is scenes of text plus search terms.
  - Kokoro TTS → Whisper captions → Pexels footage → Remotion render.
  - Exposed as a REST API and an MCP server (`/mcp/sse`).
  - Limits: Pexels-only footage, English only, about 4 GB RAM minimum, and Remotion rendering is CPU-heavy.
  - — [Glama listing](https://glama.ai/mcp/servers/gyoridavid/short-video-maker); [unpkg README](https://app.unpkg.com/short-video-maker@1.3.0/files/README.md) (secondary summaries)
- **Code2Video** (Show Lab, NUS; 2025-10): a Planner → Coder → Critic loop for Manim. The Critic is a VLM with a visual-anchor grid. It is evaluated with a VLM judge on layout, attractiveness, logic flow, visual consistency, and accuracy and depth, plus a TeachQuiz metric. — [arXiv 2510.01174](https://arxiv.org/abs/2510.01174); [Emergent Mind](https://www.emergentmind.com/papers/2510.01174) (secondary)

#### Assembly-style pipelines (good reference schemas)
- **MoneyPrinterTurbo** (MIT):
  - Topic → LLM script (many providers, including Anthropic) → stock footage (Pexels, Pixabay, Coverr, local) or AI text-to-video → TTS (Edge default) → subtitles (edge/whisper) → background music (random, local or AI) → composite.
  - Interfaces: WebUI on port 8501, API on 8080 with `/docs`, CLI with `--batch-file`, and an "AI Agent" mode using a Skill document.
  - Config via `config.toml`.
  - — [GitHub](https://github.com/harry0703/MoneyPrinterTurbo)
- **NarratoAI** (MIT, Streamlit, Python 3.12+):
  - Script JSON with OST modes; a six-stage deterministic pipeline (load script → TTS → clip → … → merge).
  - Documentary frame analysis and short-drama remix modes.
  - It switched to a single OpenAI-compatible request path after removing LiteLLM.
  - — [GitHub](https://github.com/linyqh/NarratoAI); [zread overview](https://zread.ai/linyqh/NarratoAI/1-overview) (secondary)

#### Multi-agent generative video research (2025–2026)
- **ViMax** (HKU / SCUT / HIT, 2026; MIT):
  - Agents: screenwriting, shot planning (storyboard), character styling and image generation, video generation, a VLM judge, and a hierarchical planner with RAG.
  - Models: Gemini-3-Flash is the default LLM/VLM backbone, and GPT-5.4 is used for novel-to-video planning. Keyframes use Gemini-3-Pro-Image or Gemini-3.1-Flash-Image; video uses Wan2.2 or Veo 3.1.
  - Comparing backbones, GPT-5.4 gave the best consistency. Claude-Sonnet-4.6 scored highest on some narrative dimensions but lower on consistency.
  - Results: global consistency 0.5571 vs 0.5272 for HoloCine; human-preference win rates of 60.48–77.62%.
  - Stated limitations: dependence on proprietary models; trouble with crowded, contact-heavy scenes; the video model doesn't always respect the keyframe; **no audio, dialogue sync, pacing control or interactive revision**; a 35-story benchmark.
  - Pipelines: Idea2Video, Script2Video, Novel2Video and AutoCameo, plus `vimax tui` and a Web UI.
  - Config keys: `chat_model`, `image_generator.class_path` (e.g. `tools.ImageGeneratorNanobananaGoogleAPI`) and `video_generator.class_path` (`tools.VideoGeneratorVeoGoogleAPI`).
  - — [paper](https://arxiv.org/html/2606.07649v1); [GitHub](https://github.com/HKUDS/ViMax)
- **MAViS** (arXiv 2508.08487, revised to v5 in January 2026): a multi-agent system for long-sequence storytelling, with agents for script, shot design, character modeling, keyframes, animation and **audio**. — [arXiv](https://arxiv.org/abs/2508.08487)
- **MovieAgent** (arXiv 2503.07314, March 2025): multi-agent planning of multi-scene, multi-shot films from a script plus a character bank, "ensuring character consistency, synchronized subtitles, and stable audio". — [arXiv](https://arxiv.org/abs/2503.07314)
- **AniMaker** (arXiv 2506.10540, June 2025): multi-agent animated storytelling that uses **MCTS** to generate several clip candidates and pick the one that best fits the story. — [arXiv](https://arxiv.org/abs/2506.10540)
- **Co-Director** (Google, arXiv 2604.24842): an orchestrator using a multi-armed bandit over a 3-axis creative space, plus local multimodal self-refinement. It is evaluated on GenAD-Bench, an advertising benchmark. — [project page](https://co-director-agent.github.io/)
- **AgenticGen** (arXiv 2609.09187, submitted 2026-08-31; TikTok ads): two stages, strategy selection and draft generation. They are trained with DPO, then GRPO, using a learned performance reward plus a rubric reward, with online A/B gains. — [arXiv](https://arxiv.org/abs/2609.09187)
- **NextAds** (arXiv 2603.02137) proposes personalized video advertising through creative generation and integration. — [fugumt listing](https://fugumt.com/fugumt/paper_check/2603.02137v1_enmode) (abstract-level only)
- **VideoMemory** (arXiv 2601.03655) uses Storyboard, Memory and Visualization agents. **STAGE** (arXiv 2512.12372) does storyboard-anchored keyframe multi-shot generation. **StoryAgent** (arXiv 2411.04925, 2024) uses five agents: storyline, storyboard, generation, coordination and evaluation. — [search summary links: arXiv 2601.03655](https://arxiv.org/pdf/2601.03655.pdf); [STAGE](https://fugumt.com/fugumt/paper_check/2512.12372v1_enmode); [StoryAgent](https://arxiv.org/abs/2411.04925) (abstract-level)
- **ViMax's related-work list** also cites FilmAgent, Kubrick, FilMaster, VideoDirectorGPT, VideoGen-of-Thought, GenMAC, HoloCine and StoryMem. — [ViMax paper](https://arxiv.org/html/2606.07649v1)
- **Creatify Agent / VABench**: closed system, open benchmark code (github.com/creatify-ai/VABench). Its Arm 3 is a frame-level hallucination rubric weighted 3× against structural compliance. — [Creatify report](https://d35ghwdno3nak3.cloudfront.net/videoadagent_bench/v1/research-creatify-agent.html)

### Inferences
- **Reuse map for the demo**:
  - **Install as-is**: HyperFrames core skills and CLI as the code path and the QA engine (lint, check, snapshot, measure, diff). Remotion skills are an alternative if the team prefers React. Check the >3-employee license first.
  - **Port as ideas**:
    - ViMax: keyframes before video, the shot dependency graph, best-of-2 VLM selection, and the category-routed screenwriting prompt.
    - Creatify: a typed asset graph as both spec and critic rubric; per-scene local regeneration; the hallucination rubric with a ≥3 FAIL threshold.
    - Co-Director: the 3-axis creative configuration (strategy × narrative mode × aesthetic archetype) for generating variants.
    - Code2Video: grid anchors in VLM critiques of layout.
    - product-film-skill: a BRAND.md "source of truth wins" rule, three style frames before building, and a beat grid.
  - **Copy schemas**: NarratoAI's script items (timestamp, picture, narration, OST) for reference-video remix and narration flows, its JSON-repair cascade for LLM outputs, and MoneyPrinterTurbo's edge-vs-whisper subtitle strategy and batch-file validation.
  - **Skip as runtime**: ViMax and the other research pipelines. They're Python research code built around generative-only output, with no audio or edit loop. Use them as design references.
- **Suggested Agent SDK architecture.**
  - One orchestrator `query()` session per chat thread, resumed per turn.
  - Subagents defined programmatically: `planner` (brief → script → shots), `critic` (vision QA over contact sheets with a rubric JSON), and `reference-analyst` (Q4 pipeline).
  - Skills from the filesystem: `hyperframes`, `hyperframes-cli`, `media-use`, plus a custom `ad-video` skill holding the routing table, the project.json schema and QA thresholds.
  - Custom tools via an in-process MCP server for the generative APIs (Grok Imagine, Kling, Seedance, Veo), TTS (ElevenLabs with-timestamps, Kokoro) and the content-addressed asset cache.
  - Bash for the FFmpeg, scenedetect and hyperframes CLIs, with `HF_TOOL_CONTEXT` set so contact sheets and findings come back as structured events.
  - Each turn appends JSON-Patch ops plus tool events to a trajectory log, covering the project's "trajectory logging" requirement.
